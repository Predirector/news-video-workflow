# 对话要求落实与验收矩阵

这里区分“规则写明”“默认渲染实现”“自动可测”“仍需实际审看”。没有把无法自动判断的审美/事实问题打成自动通过。细则以[完整标准](editorial-rules.md)的R01–R13为准。

| 对话里反复提出的具体要求 | 落实位置/需要什么 | 验收与边界 |
|---|---|---|
| 飞书参考片学习、先控制10种样式 | reference_scan.py真实抽帧、reference-library.md样式卡与验证流程 | 字体/音乐未知就记录未知；当前仅3套实际合成，不把10个名字当模板 |
| 一切围绕这条稿子想表达的核心 | `production-plan.json`的coreMessage、coverReason、每镜claim/assetWhy；R01 | `production_audit.py`要求逐镜计划；语义是否准确仍实际审稿 |
| 同批不能一模一样，不能只换颜色 | plan.batchDifferences；三套font/字号、底托、画幅、圆角、板型；R01/R09 | 并排比较同批实际成片；不是换文件名/裁切就算变化 |
| 原稿主副标题不能被自行改掉 | `expectedTitles`、共用Header、R02/R05 | `common.validate`逐字比对；修改封面同步前三帧 |
| 字体要真实粗、有重量，不能一套字用到底 | `font-catalog.json`、fontPreset、三角色字体、R03 | 官方文件哈希、FontTools字重/缺字；`font-audit.json`；`fontSynthesis:none` |
| 原来用方正/苹方的样式不能冒充复现 | `news.py fonts`导入使用者自己的文件；custom preset | 不分发方正/系统字体；缺文件停下，不悄悄改宋体；原样复刻与新默认分别说明 |
| 花字要有剪映类似厚度，不是扁平文字 | Header的字面厚度与局部底托、字体角色；R03/R04 | 真实Remotion静帧+360px手机图；不承诺等同剪映花字引擎 |
| 黄色不显就加底，别红底黄字再白描边 | speed-yellow深底黄字，其他白字色块；R03 | 默认无粗白边；自定义配色需实际反差检查 |
| 标题居中、不歪、不靠顶 | `visual.py`测量header、Root居中水平布局 | y≥240、字宽/板块间距自动约束；实际主体和平台裁切审看 |
| 压缩标题区，副标题可放一行 | 根据实际字体测字宽和组高；副标题独立字重42px | 不截字；超长要求语义断行，禁止不断缩小正文字号 |
| 画面不能压扁/白边/空条 | Media等比cover与可配置crop；原件尺寸校验 | 精确构图、姓名/人脸/事件字是否被裁仍逐镜看；不能用固定裁切解决所有图 |
| 图尤其人物不能变黑白 | 前景Media无灰度/压黑滤镜；背景独立滤镜 | 照片主导屏审肤色和亮度；自定义代码也要检查 |
| 背景不是纯色/纯渐变，要粗粝真实 | Background固定种子纸纹、点阵、局部色层；可选实景微动 | 实际手机图检查纹理可见且不抢视觉；不强制全部用实景 |
| 实景模糊但不压暗，要整体明亮 | 背景brightness、blur与低透明度独立于主体 | 原图过曝/颜色发脏不能靠同一个参数通吃，需当期调整 |
| 上下留白可有语义图形但不抢 | R09+plan.backgroundReason，按主题扩展Background | 当前默认不是任意主题自动生成器；图形需说明示意属性 |
| 封面要直接说明核心，不能乱拼 | plan.coverReason与R05；cover.asset | 人工按缩略图检查；默认工具不自动判断“多城/接连签约”是否被表达 |
| 封面所有核心元素严守中央3:4 | `visual.py`、`production_audit.py` | 标题/图槽/关键词块边界；原图主体是否完整仍审看 |
| 封面别放零散解释碎字 | cover.keywords最多2行、无额外图注层 | 实际文案要短且必要；不能把两段长说明当2个关键词 |
| 前3帧静态封面，第4帧开正文 | Root Freeze/Sequence；verify.py | 全帧验证前三帧与静态封面；音画时码含0.1秒 |
| 报道必须原版面，不允许自己排 | screenshot.mjs/真实PDF裁片；evidence.original；R06 | 工具只截原DOM；原文真实性需看原链接和原图，bool不等于证据已核验 |
| 长竖报道改横向完整段落 | 原图裁片、等比缩放；R06 | 不改原断行/字体、不裁半字；不把窄竖条缩小冒充可读 |
| 英文报告要提炼翻译并对应 | R06、plan.originalReport；独立中文信息区 | 中文不覆盖原文；译意逐项回到原文核对，默认不自动翻译整页 |
| 标记只保留一种，跨行分别标 | `mark`或`marks`单一系统、逐矩形时间；R06 | 自动查重复系统/越界；实际文字坐标和语境需看截图 |
| 新闻/现场交叠别导致图片展示两次 | 每镜assetWhy、原报道配图裁除策略；R06/R07 | 人工比对原图与报道片段，不能只靠文件哈希判断 |
| 资讯板逐字，但原声正常字幕 | Text固定行opacity；mode分支；R08 | 字体实测换行；看打字早/中/全文完成帧及同期句对齐 |
| 下方资讯板居中且手机易读 | 新闻48px、同期54px、逐行居中；长句拆屏 | `visual.py`测量行宽/板高，不够则报错；360px预览看最密屏 |
| 关键字要重点，但不要盖住字 | 正文单一浅色底、原报道低透明底；R06/R08 | 不叠划线；关键词必须与原稿对应，不全句乱高亮 |
| 全文出现后留阅读时间，不能刚出完就走 | reveal时间和至少约30帧尾停；common阅读时长门槛 | 自动门槛+实际观看，不用牺牲条件/漏字卡时长 |
| 原声人物说完立即接资讯，不乱盖排名图 | R08、逐镜时间线与原稿关系 | 当前starter按mode单模式，混合采访→资讯需按原声区间扩展合成；未谎称有全自动混合模式 |
| 原声提速不变调，字幕画面一起动 | prepare.py atempo与时间映射 | 配置speechRate；本批1.1不升级成所有片的无条件默认 |
| 每屏柔和过渡、背景微动 | Root连续背景+6帧交叉淡入；无CSS动画 | 检查实际编码边界，保持字幕读完，不能靠转场掩盖闪帧 |
| 快，尤其前面快，尽量20秒内 | common上限及durationReason；R10 | 超时说明；原声与阅读必要时例外，不能机械剪掉信息 |
| 好看镜头前置，素材丰富且对应 | R07、plan.shots逐镜claim→assetWhy | 实际核对身份/事件/年份；行业素材不代替当次签约/获奖 |
| 素材近邻重复和短闪镜头要消除 | 图片内容哈希近邻检查、verify短闪候选；R07 | 固定机位、相似裁切和源视频内部切点仍逐帧审看 |
| 来源内部标签不能上视频 | R06/R11，来源在reports/materials.json | 标题/图注不能加“用户提供/资料图/官网/内部公稿”；原报道本身公开信息不是内部标签 |
| 音乐来自抖音渠道，不必热榜 | plan.music.discoveryUrl与实际音源、R10 | 记录核实状态，不能把合成演示节奏或随手NCS称抖音热曲 |
| 快讯音乐要推进，不要慢悠悠 | 实际选段试听记录excerptReason/listenedExcerpt | 听感是人工判断，BPM/曲名不能代替；具体爱国/歌词点是单期要求 |
| 连贯、不重复、开头剪干净 | prepare连续段、时长检查；usedMusicCheck | 不暗中拼接循环；实际试听曲头/尾，查同系列已用曲 |
| 切镜/板子/文字跟音乐节点 | music_analysis.py候选onset、plan.music.beatDecision | 候选不等于正确重拍；换曲后重排，不挪口型硬卡 |
| 有原声也要BGM，不抢讲话 | prepare语音与音乐独立混合、避让和峰值检查 | 实际听感验收；不以波形数值代替可懂度 |
| 缺素材自己网上找、B站可登录1080 | news.py search/fetch/collect/intake、R11 | 使用者自己的账号；记录实得高度、失败原因，不绕权限 |
| 下载目录用完归拢清掉 | import哈希校验、R11清理授权分支 | 当前导入工具不删个人下载；当前用户授权+依赖核对后执行 |
| 定版只留最终+可运行工程 | cleanup.py登记过程文件、清理后渲染；R11 | 当前工具只清登记项；整期额外未用素材先核对，不扩大删共享库 |
| 按脚本完整编号标题命名 | name/expectedTitles、verify产物；R02/R12 | MP4/封面/草稿/素材包分别沿用，不附临时版本后缀 |
| 每条打包全部实际素材与成片 | R12条件分支 | 公共包未带打包器；有需求时实现并解包重建验证，不能声称现成 |
| 剪映背景/画面/文字/底板分离，同类同轨 | R12条件分支 | 公共包未带转换器；需要实际剪映打开验证可编辑文字，不能只导入整片 |
| 先搭视觉、再制作，以及规则持续沉淀 | R13、生成工程AGENTS、详细规则与视觉基准 | 用户要求先审才等待；否则内部自检继续。规则更新不自动覆盖已创建工程 |

## 可公开的默认视觉基准

`assets/visual-baselines/`只放本包自制演示的实际封面、正片手机图和字体/布局记录。它用于检查安装后是否载入正确字体及结构，不是用户历史所有样式的“原样复刻”，也不是事实/选材/音乐审片的替代。

方正汉真广标等需要使用者自己文件的风格，必须显式标注。三个起始模板不冒充已经做齐最初设想的10套样式；扩充模板库时每套都要有对应实际渲染、字体来源和适用主题。
